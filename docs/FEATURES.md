# Feature status — v0.2

**Status terminology:** “Implemented” describes executable source and, where listed, an editor command. “CPU-tested” means algorithm/format/host tests were run. “DOM-tested” means the actual UI was exercised without a GPU. “GPU-unverified” means the changed WGSL/pipelines could not be compiled or dispatched in this environment. It does not mean passed, production-qualified, or pixel-equivalent to another product.

## Modeling and UV

BSP solid union/subtraction/intersection split polygon planes, interpolate cut UVs, retain operand material tags and stitch T-junctions before manifold checks. Overlapping, coplanar and disjoint cube cases, closed topology and signed volumes are CPU-tested. Inputs must be closed, outward-facing, consistently oriented manifolds. There is no exact-predicate or arbitrary pathological-solid guarantee. Limits include 50,000 input faces and a 12,000-position stitching budget; oversized work rejects explicitly.

The bevel modifier constructs inset faces, one-segment edge strips and mitered vertex caps. It is a convex-solid chamfer, not a general multi-segment bevel. Concavity, open boundaries, coplanar triangulation edges and overlapping widths reject. Boolean and bevel use the same editable polygon meshes as existing extrusion, inset, deletion, weld and modifiers.

UV tools split local corner sectors across seam edges, including a longitudinal seam whose sides remain in one connected face chart. Automatic seams retain smooth dual spanning forests so closed surfaces open into charts. LSCM solves a sparse least-squares conformal system with pinned values; relaxation uses inverse-distance Laplacian weights; deterministic shelf packing scales and places islands. Island rotation, scale, translation, pinning and coincident-position stitching are exposed. Tests cover a cube, smooth sphere, cylinder seam, pinned mapping, padding and metadata. These algorithms do not promise zero flips, zero overlap, optimal packing or distortion-free parameterization. One UV set is stored; no UDIM, texture painting, bake cage or channel stack.

## Rigging, animation and simulation

Chain binding creates inverse-bind matrices and normalized four-influence weights. Linear blend and dual-quaternion skinning evaluate actual mesh positions/normals. Dual-quaternion mode rejects non-rigid bone scale rather than approximating it silently. Bone quaternion keys and imported glTF channels are sampled; FABRIK handles reachable/unreachable targets and optional pole direction, with Euler limit support in the solver API. The UI edits bone poses, keys and numeric influences. There is no weight-paint brush, automatic character rig, constraint stack, retargeting, muscle model or persistent IK-controller graph. IK writes a pose rather than running an independent controller at every animation sample.

Object transforms retain step/linear/smoothstep keys and the existing curve editor. glTF tracks add STEP, LINEAR/slerp and CUBICSPLINE channel sampling. Imported tracks and the original editor keys are different representations, not a unified controller graph; manually editing an imported tracked channel is not automatically an edit to its track.

XPBD implements structural, shear and cross-edge distance/bend constraints, fixed pins, gravity, damping, floor and sphere colliders. `RigidWorld` exposes angular integration plus sphere-sphere/floor contacts. **The editor's per-object `SimulationCache` creates individual object-local worlds; bodies attached to separate scene objects do not collide with each other.** API callers can place multiple proxies in one `RigidWorld`. Render geometry is not the collision hull. No mesh-mesh/convex-hull collision, cloth self-collision, fluids, smoke simulation, FEM, fracture or soft-body volume constraints.

Fractional shutter samples advance a temporary physics state and restore the integer-frame checkpoint, supporting deterministic random-order sampling. Backwards seeks restart from rest. Baking writes per-frame positions; playback linearly interpolates those positions. Rigged animated collision/rest targets, topology-changing caches and Alembic-style streaming are not implemented.

Hair grows seeded area-weighted surface roots, clump/curl centerlines and parallel-transport tube meshes. Optional XPBD root-pinned strand dynamics are CPU-evaluated. Hair follows the evaluated source surface but is not a groom with guide interpolation, brush tools, strand self-collision, dedicated curve intersections or fiber-scattering lobes. Particle emitters generate deterministic fixed-step ballistic particles with a floor collision; octahedral meshes reach both renderers. No GPU particle solver, node-based effects graph, sprite atlas or arbitrary scene collider binding.

## Materials and transport

RGBA8 source bitmaps are retained in native scenes and converted to equal-sized square GPU array layers. Sampling decodes sRGB; mip generation averages linear light. Sixteen graph node types compile to bounded instructions: constant, UV, position, add, subtract, multiply, divide, mix, clamp, checker, noise, image, ramp, sine, channel and power. Surface outputs connect base color, roughness, metalness, emission, transmission, IOR, subsurface weight and density. The visual graph editor arranges nodes and edits actual connections. Graph validation rejects missing inputs, cycles and excess nodes. CPU references test graph arithmetic; **GPU graph/raster/path evaluation remains unverified**.

No arbitrary shader-source language, closure tree, measured layered materials, tangent-space normal/bump/displacement texture workflow, automatic ray-differential LOD, UDIM streaming or alpha-cutout transport. A bitmap's alpha is retained but not used as surface coverage by the renderer. The material model has diffuse/GGX reflection and ideal smooth dielectric transmission, not rough refraction. Emission color is coupled to the material's evaluated base color.

World volume transport samples a homogeneous axis-aligned box using exponential free flights and Henyey–Greenstein scattering, including next-event estimation/transmittance. Closed scattering solids use homogeneous interior random walks. This is not heterogeneous VDB transport, a diffusion-profile system, calibrated skin/hair presets, a nested-medium stack or overlapping media. A single active interior object is tracked. These revised transport paths are **GPU-unverified**.

Photon mode emits surface photons from mesh/environment sources, traces up to eight photon vertices, stores indirect hits in atomic linked spatial cells and gathers a cone-kernel estimate. Final gathering traces an additional non-delta surface bounce before gathering. Direct lighting is evaluated separately; first-hit direct photons are excluded to avoid double counting. Storage is bounded by configured count; hash collisions are checked against the actual spatial cell. This is a **biased, surface-only GPU-unverified estimator**, not stochastic progressive photon mapping, volume photons, irradiance caching or a complete final-gather control system. Volume/SSS combinations explicitly require the path integrator.

## Production rendering, output and coordination

A production frame evaluates camera, transforms, bones, cache/procedural geometry at stratified shutter times. Static shutters reuse compiled geometry. Moving geometry uses quality-bounded refits or rebuilds. This is actual scene-time integration, not a post-process smear; **its GPU output is unverified**. CPU deformation is recomputed per sample and can be expensive. No rolling shutter, velocity-buffer blur, temporal BLAS or animation-sequence render UI.

AOVs are raw albedo, shading normal, depth, object ID, emission, direct and indirect plus beauty. Direct plus indirect is defined to reconstruct beauty. Object IDs are compiled one-based indices, not stable named mattes; the latest camera sample's ID is kept rather than averaged. At antialiased/blurred boundaries other AOVs average samples. There is no Cryptomatte, deep sample stream or arbitrary render-element plug-in API.

The a-trous denoiser is a 5×5 edge-aware filter with 1–5 dilation passes, guided by color, normal, depth, albedo and object ID. It writes separate buffers, leaving raw beauty/AOVs untouched. No learned model, temporal reprojection or reference-image quality qualification. **GPU-unverified**.

EXR encoding supports single-part, uncompressed scanline FLOAT and UINT channels and metadata, including the 21-channel render bundle. The project subset decoder round-trips AOV/UINT values. OpenCV independently decoded RGB FLOAT test data and preserved negative/high-dynamic-range values; it did not validate arbitrary AOVs. Pillow independently decoded the original PNG encoder. GPU readback plus EXR end-to-end remains unverified. No HALF, compression, tiled/deep/multipart EXR or EXR scene-texture import workflow.

The Node coordinator's actual HTTP API is tested: authenticated jobs, bounded payloads, origin allowlist, deterministic tile/sample allocation, leases, heartbeat, expiry/requeue, stale-result rejection, idempotent duplicates, compensated weighted merge, status/cancel/purge and EXR download. Browser workers call the same renderer/tile API. **No multi-GPU distributed render was executed here.** Jobs live in memory; no durable queue, restart recovery, worker discovery, cloud provisioning, tenant isolation, scheduling fairness or TLS deployment automation. Localhost is the default; remote use requires HTTPS and access-control configuration.

## Interchange and retained editor

GLB/glTF import/export handles hierarchy, static meshes, material primitives, hard-edge vertex remapping, base-color bitmap assets, four-weight skins, morph positions and transform/weight animation. Import reads strided/normalized/sparse accessors and triangle/strip/fan primitives; the selected animation clip defaults to the first. CPU tests cover structural/geometry round-tripping, not certification by the Khronos validator. Unsupported required extensions and malformed resources reject. Optional unsupported PBR channels/alpha are reported as warnings; they are not silently claimed to render. Multiple scenes/clips, normal morphs, non-TRS shear, compressed geometry/textures, higher UV sets and extended material workflows are incomplete. Native graph/SSS metadata in glTF extras is not a portable material shader. Topology-incompatible skin/morph exports reject.

ASCII PLY exchanges polygon geometry with baked transforms; extra scalar vertex data is ignored after validation. USDA export writes evaluated mesh snapshots with a UV primvar and scene units. It is not a USD importer, compositor, variant/layer system or skeletal/animation USD exporter. Existing OBJ/STL tools remain; broader production formats such as FBX, Alembic, full USD, `.max` and `.mi` are not supported.

The editor retains searchable hierarchy, transforms, multiple selection, modifiers, polygon/vertex tools, UV workspace, material editing, timeline/curves, undo/redo, recovery and native files. No claim of all views, all shortcuts, every tool, scripting/plugin compatibility, accessibility certification or pixel-identical commercial UI is made.
