# Feature status and remaining scope

This file distinguishes a working implementation from feature parity. “Implemented” means code is connected to the application or public modules; it does not mean a feature has the depth, production validation or interoperability of a mature commercial tool. Tests are enumerated separately in TESTING.md.

## Implemented editor and geometry

| Capability | Implementation and boundary |
|---|---|
| Scene management | Named objects, search, hierarchy, visibility, camera visibility, locks, multi-object selection, duplicate/delete, native documents. No layer manager, XRefs or asset resolver. |
| History | Atomic snapshot undo/redo; 60 entries and approximate 64 MiB budget. Not an unlimited large-scene history. |
| Transforms | Numeric local position/Euler rotation/scale; interactive translation, Euler rotation and scale handles; world/local translation axes; grid and rotation snapping. No editable pivots or general world-space rotation manipulation. |
| Camera navigation | Orbit, pan, dolly, frame selection; perspective, top, front and right orthographic views; pinch dolly. One working view at a time, not quad view. |
| Primitives | Box, sphere, cylinder/frustum, cone, torus, plane, capsule and lathe. Numeric parameters are editable. Lathe profiles are editable through document/module data, not a graphical profile-drawing tool. |
| Polygon geometry | Indexed polygons, finite-value/index validation, simple planar concave polygon triangulation. No exact-predicate general solid kernel. |
| Components | Single-face selection, nearby vertex selection and vertex translation. No edge-selection mode, polygon-region selection or topology brush. |
| Extrude / inset | One selected polygon, connected side walls or centroid-relative inset ring. Inset is a fraction toward the face centroid, not a constant-distance offset solver. |
| Face delete / weld | Face removal and quantized coincident-vertex welding. Welding regenerates planar UVs; it is not a UV-preserving topology repair system. |
| Linear subdivision | Non-destructive face refinement; topology is actually generated. UVs are regenerated by projection. |
| Catmull–Clark | Actual surface subdivision with boundary rules, up to three levels per modifier. No crease weights, adaptive subdivision or production nonmanifold repair. |
| Twist / bend / taper | Position deformation relative to mesh Y extent. No arbitrary modifier gizmo transform or axis selector. |
| Displace noise | Deterministic analytic trigonometric displacement along computed normals. No external height-map displacement or named procedural-noise compatibility. |
| Mirror | Reflected duplicate across an X plane, with winding correction. No automatic seam welding, clipping or symmetry topology editing. |
| Shell | Offset inner vertices, reversed inner faces and boundary walls. Not an exact constant-thickness solid offset with self-intersection cleanup. |
| Stack | Add, enable, reorder, remove and collapse. Topology editing bakes the evaluated stack and is undoable. No plugin modifier ABI. |
| UVs | Per-vertex coordinates, dragging and planar/spherical projection. Shared vertices share UVs; no seams, islands, packing, UDIMs or multiple UV channels. |
| Materials | Shared material library and real assignment/editing. Library balls are illustrative CSS previews, explicitly distinguished from GPU rendering. |
| Animation | Transform keys, auto key, playback, frame range/FPS, key deletion/navigation, step/linear/smoothstep, draggable curve keys. No tangent handles or general controller graph. |
| Workflow UI | Modeling/material/animation/render workspaces, property tabs, command palette, menus, shortcuts, dialogs, responsive panels and explicit error messages. Not a pixel clone of another product's UI. |

## Implemented renderer

| Capability | Implementation and boundary |
|---|---|
| Raster preview | Native vertex/fragment pipeline; shared geometry/material buffers; preview lights, grid, selected edges and wireframe. No raster shadow-map system or real-time indirect illumination. |
| Final rendering | Actual WebGPU compute path tracer; progressive float32 accumulation. No CPU renderer fallback disguised as WebGPU. |
| Acceleration | Worker binned-SAH BVH, flattened triangles, exact-bound refitting, quality/generation rebuild policy. No instancing or hardware ray-query extension. |
| Surface scattering | GGX reflection, diffuse, metallic mixing, IOR, ideal smooth dielectric Fresnel transmission. Not a complete layered/spectral material model. |
| Lighting | Mesh area lights, analytic sky gradient, mesh/environment next-event estimation and MIS. No IES lights, HDRI loading, explicit spot/directional light types or portal importance sampling. |
| Indirect illumination | Multiple surface bounces with Russian roulette and a configurable depth limit. No irradiance cache, final-gather cache, photon map or bidirectional transport. |
| Emission | Shared material emission, area/luminance-weighted CDF and matching light-hit PDFs. No light linking or per-light render layers. |
| Patterns | UV checker and world-space marble/wood. No bitmap texture decoding, normal maps, bump maps or texture node graph. |
| Camera | Perspective/orthographic rays, lens aperture radius and focal plane. No animated multi-camera system, fisheye/panorama lenses or shutter motion blur. |
| Diagnostics | Albedo, normals, depth and object-ID display modes; sample/triangle counts; device limits and validation errors. Not a production AOV/render-element framework. |
| Output | Display-mapped PNG and unclamped linear float32 PFM. No EXR, multilayer output, alpha compositing, tiled farm output or video encoding. |
| Color | Linear shader math, exposure, filmic fit, sRGB display encoding. No OCIO configuration, color-managed bitmap input or full ACES pipeline. |
| Sampling | Uniform progressive per-pixel sample count, bounded queue submission and deterministic PCG-derived samples. No adaptive sampling, temporal/spatial denoiser or out-of-core paging. |
| Device handling | Adapter checks, shader compilation diagnostics, explicit buffer limits, reported device loss. Automatic device restoration is not implemented. |

## Interchange contract

| Format | Import | Export | Important losses |
|---|---|---|---|
| `.aureon` v1 JSON | Yes | Yes | Native document round trip; UI selection/layout and GPU caches are intentionally not serialized. |
| OBJ | Positions, polygons, UV tuples and relative indices | Evaluated world-space polygons | Export is geometry-only: no MTL, UVs or normals. Import ignores material libraries and source normals. |
| STL | Binary and ASCII triangle meshes | Binary world-space triangles | No materials, animation, hierarchy or UVs; imported vertices are welded and UVs regenerated. |
| glTF 2.0 | No | Embedded static geometry/PBR snapshot | No animation, cameras, scene-light semantics, procedural patterns, transmission extension or high-intensity emission preservation. Explicit normals are not exported. |
| PNG | No texture import | Retained GPU display image | 8-bit display mapping, not linear HDR. |
| PFM | No image/environment import | Float32 linear RGB | No alpha or scene metadata; bottom-up little-endian float data. |
| `.max`, `.mi`, FBX, USD, Alembic | No | No | No undocumented/native compatibility claim. |

## Major unimplemented product scope

| Production area | Work still required; no corresponding completed-feature claim |
|---|---|
| Advanced modeling | Boolean/CSG solids, bevel/chamfer, bridge/cut/connect tools, edge loops, multi-region extrusion, robust symmetry, retopology, sculpting, NURBS and full spline/surface modeling |
| Procedural geometry | Node graph, geometry instancing, arrays/scatter, modifier controllers, procedural asset definitions and a larger modifier catalog |
| Rigging and character animation | Bones, skinning, morph targets, IK/FK, constraints, rig controls, animation layers, nonlinear clips, retargeting and motion capture |
| Simulation | Rigid/soft bodies, cloth, fluids, particles, hair/fur/grooming and physically coupled simulation caches |
| Production materials | Texture images/UDIMs, node-based shading, layered lobes, rough transmission, SSS, participating media, nested dielectrics and spectral transport |
| Legacy renderer techniques | Photon maps, final gathering/irradiance caches, dedicated caustic solvers, displacement tessellation, shader/plugin-language compatibility and legacy scene syntax |
| Render production | EXR/AOV pipelines, denoising, adaptive sampling, robust caustics, motion blur, distributed rendering, batch animation rendering, render farms and render layers |
| Large-scene performance | BLAS/TLAS instancing, GPU BVH builds/refits, worker-based mesh evaluation, GPU deformation, out-of-core geometry/textures, profiling and hardware-specific optimization |
| Interoperability | Broader glTF import/export, FBX/USD/Alembic workflows, versioned asset resolution, native-file research and independently specified compatibility tests |
| Extensibility and pipeline | Stable plugin SDK, scripting console/language, command automation contracts, collaboration, asset management and external production integrations |
| Product qualification | Cross-vendor/browser GPU testing, image-reference conformance, statistical convergence testing, accessibility audit, large-scene memory pressure tests and production stability testing |

The development order should preserve a working editor-to-renderer path: add an operation to the core library, give it correctness tests, connect it to real UI/document state, add interchange semantics where applicable, then qualify it in the renderer. A disabled menu entry or illustrative image is not a substitute for implementation.
